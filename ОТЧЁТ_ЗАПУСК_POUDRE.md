## Состояние после исправлений

Лендинг развёрнут в Vercel Production и доступен по ссылке [https://poudre-seven.vercel.app](https://poudre-seven.vercel.app). Открытие публичной страницы в браузере подтвердило, что сайт отображает Poudre.

Стандартный скрипт запуска теперь адаптирован к Windows: обёртка вызывает JS CLI Vite через Node, а не пытается запустить `vite.cmd` непосредственно. Добавлены тесты этого поведения. Production-сборка `npm run build` проходит; локальная страница отвечает `HTTP 200`.

## Первоначальные причины

### 1. Windows-обёртка не могла запустить команду Vite

Скрипт `dev` в [`package.json`](./package.json) запускает `scripts/with-app-env.mjs`, который запускает команду `vite` с помощью `spawn(command, args)` в [`scripts/with-app-env.mjs`](./scripts/with-app-env.mjs). На Windows npm предоставляет исполняемый файл Vite как `vite.cmd`; прямой `spawn("vite")` не запускает такой `.cmd`-файл. Поэтому сервер завершался с сообщением `spawn vite ENOENT`.

Установка зависимостей прошла, Vite был установлен; повторный `npm ci` сам по себе проблему не исправил. Прямой запуск JavaScript-файла Vite обошёл ошибку. Это исправлено в `scripts/with-app-env.mjs`.

**Обходной запуск в PowerShell:**

```powershell
Set-Location 'E:\01_poudre\nwiNilY1SlIn3Pcc-grok-workspace'
$env:VITE_AUTH_ENABLED = 'false'
node node_modules/vite/bin/vite.js dev --host 0.0.0.0 --port 8080
```

Теперь предпочтительный способ — стандартная команда `npm run dev`, вызывающая исправленную обёртку.

### 2. Публикация исходников не выполнила деплой сайта

Репозиторий GitHub — хранилище кода, а не работающий сервер приложения. В изученной конфигурации [`vercel.json`](./vercel.json) задана только команда установки пакетов; она не сообщает адрес опубликованного сайта и сама по себе не подтверждает, что деплой состоялся. Приложение использует TanStack Start и Nitro ([`vite.config.ts`](./vite.config.ts)); для его серверных маршрутов нужен хостинг, который запускает серверную часть. GitHub Pages сам по себе такой сервер не запускает.

В публичном репозитории есть исходники приложения и нужные каталоги (`src/routes`, `src/lib`). Исправления опубликованы в GitHub; Vercel подключён к репозиторию и автоматически собирает новые версии.

Vercel-конфигурация до исправления выполняла `npm install --omit=dev`, что исключало необходимые при сборке инструменты из devDependencies. Установка теперь использует `npm ci --include=dev --no-audit --no-fund`. В манифест добавлено требование Node.js `>=22.12.0`, подходящее для текущей версии Vite.

В репозитории также присутствуют шаблонные GitHub Actions для Deno, Webpack и публикации npm-пакета. Они не разворачивают сайт; workflow Webpack использует `npx webpack`, тогда как проект собирается через Vite. Они не мешают локальной production-сборке, но их стоит заменить на проверки, соответствующие проекту.

## Что подтверждено проверками

- Локальный адрес `127.0.0.1:8080` ответил `HTTP 200`; браузер ранее показал страницу Poudre.
- [`npm run build`](./package.json) завершился успешно и сформировал Vercel/Nitro output; миграция пропущена штатно, так как `DATABASE_URL` не задан.
- [`npm run typecheck`](./package.json) завершился успешно; `npm test` прошёл, 59 тестов успешно.
- Unit-тесты обёртки прошли 13 из 14: оставшийся тест требует создания symlink в Windows и завершился системным `EPERM` (отказ в доступе), а не ошибкой запуска приложения.
- Production-сборка сайта завершилась на Vercel; публичная страница `https://poudre-seven.vercel.app` подтверждена открытием в браузере.
